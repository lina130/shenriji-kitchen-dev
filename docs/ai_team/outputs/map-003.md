# 多场景城区合理分区与入口密度

## 主方案

# 多场景城区合理分区与入口密度 —— 唯一可执行方案

> 综合裁决：以 **world-002 的三层几何不变量系统** 为骨架，吸收 **world-001 的连续城区流式加载** 与 **npc-001 的 NPC home_area 归属**，按批判报告逐条闭环。本方案**只做分区数据 + 门配对 + 密度审计 + 存档迁移**，不重写流式加载架构（那是 world-001 的职责）。
>
> **核心目标**：把当前堆在 `street` 单场景的 8 个 zone（market/village/nature/commercial_shops/commercial_services/industrial/suburb/center/activity）拆到 7 个连贯场景，每个场景入口数受控，道路连接显式声明，门配对唯一化，旧存档可无损迁移。

## 一、决策（先拍板，再执行）

### 1.1 现状诊断

`data/scene_zones.csv` 当前问题：

| 问题 | 证据 | 后果 |
|---|---|---|
| **单场景过载** | `street` 一个 area_id 挂了 9 个 zone（market/village/nature/commercial_shops/commercial_services/industrial/suburb/center/activity） | 玩家在一条街上看到全部业态，无分区感 |
| **业态混杂** | `commercial_shops`（商业）与 `industrial`（工业）在 `street` 内相邻（y=900 vs y=60） | 违反"温柔治愈"约束，工业区紧贴商业区 |
| **kind 语义冲突** | `commercial_district` 用 `services`，`street` 也用 `services`（commercial_services） | 审计器无法按 kind 区分 |
| **无门配对** | 无 `doors.csv` | 场景切换靠 `travel_to` 硬跳，无入口密度控制 |
| **无道路定义** | 无 `street_segments.csv` | 无法验证"相邻街区连续道路" |
| **无碰撞登记** | 无 `colliders.csv` | 空气墙无法审计 |

### 1.2 目标场景划分（7 个连贯场景）

按任务要求拆为：**居住区 / 早餐街 / 商业区 / 工业区 / 市场 / 河畔 / 自然景观**。

| # | area_id | 中文名 | kind | 承载原 zone | 入口上限 |
|---|---|---|---|---|---|
| 1 | `residential` | 居住区 | `residential` | `street.village` + `street.suburb` + `home` | **3** |
| 2 | `breakfast_street` | 早餐街 | `commercial` | `breakfast_shop` + `breakfast_kitchen` + 新增早餐摊 | **4** |
| 3 | `commercial_district` | 商业区 | `commercial` | `street.commercial_shops` + `street.commercial_services` + `commercial_district.*` | **5** |
| 4 | `industrial_district` | 工业区 | `industrial` | `street.industrial` + `industrial_district.*` | **3** |
| 5 | `market` | 市场 | `market` | `street.market` + `market` + `night_market` | **4** |
| 6 | `riverside` | 河畔 | `riverside` | `riverside` + 新增河畔步道 | **3** |
| 7 | `nature` | 自然景观 | `nature` | `street.nature` + `park` + `mountain_spring` | **2** |

**入口上限定义**：一个场景内**可被玩家点击进入的门的最大数量**（含通往其他场景的门 + 通往室内的门）。上限用于防止"一条街堆 20 个店面"。

### 1.3 关键裁决表（逐条闭环批判）

| 批判项 | 裁决 | 落地位置 |
|---|---|---|
| kind 全局唯一 | 新增 `living` / `riverside` kind，删除 `services` 复用 | §2.1 |
| 密度表空表 | 密度由 `street_segments.csv` + `doors.csv.is_shop_entrance` 计算 | §2.3 |
| 重叠判定 off-by-one | 统一 `<=`，相邻不算重叠 | §3.1 |
| door_rect 方向 | `doors.csv` 新增 `orientation` 列（`ns`/`ew`） | §2.2 |
| 存档兼容 | 旧 `interaction_id` → 新 `door_id` 映射表 | §5 |
| 空洞未填满 | 逐格扫描验证并集 == map_size | §4.1 |
| target_spawn 语义 | 只存 spawn 名，D2 只比较 `area_id` | §2.2 |
| 空气墙边界判定 | 矩形与 zone 边界交集非空 | §3.2 |
| find_holes off-by-one | 连通块合并（BFS） | §3.1 |

## 三、审计器 `tools/audit_zones.py`（CI 门禁）

### 3.1 几何不变量检查

```python
# 伪代码，实际实现见 tools/audit_zones.py
def audit_geometry(zones, doors, colliders, segments, map_size):
    errors = []
    
    # R1: 同 area 内 zone 两两不相交（<= 判定）
    for area_id, area_zones in group_by(zones, 'area_id'):
        for a, b in combinations(area_zones, 2):
            if rect_intersects(a, b, inclusive=True):  # <= 判定
                errors.append(f"R1: {a.zone_id} 与 {b.zone_id} 重叠")
    
    # R2: 所有 zone 并集 == map_size（逐格扫描 + BFS 连通块）
    grid = build_grid(map_size, resolution=16)
    for zone in zones:
        if zone.parent_area == "":  # 只检查 outdoor
            mark_grid(grid, zone)
    holes = find_holes_bfs(grid)  # 连通块合并
    if holes:
        errors.append(f"R2: 发现 {len(holes)} 个空洞: {holes[:5]}")
    
    # R3: 门成对出现
    door_pairs = {}
    for door in doors:
        key = (door.from_area, door.to_area)
        door_pairs.setdefault(key, []).append(door)
    for (a, b), ds in door_pairs.items():
        if (b, a) not in door_pairs:
            errors.append(f"R3: {a}→{b} 无反向门")
    
    # R4: 门不覆盖碰撞体
    for door in doors:
        door_rect = build_door_rect(door)
        for col in colliders:
            if col.area_id == door.from_area and rect_intersects(door_rect, col):
                errors.append(f"R4: {door.door_id} 被 {col.collider_id} 覆盖")
    
    # R5: 入口密度
    for area_id, area_doors in group_by(doors, 'from_area'):
        shop_entrances = [d for d in area_doors if d.is_shop_entrance == 1]
        limit = ENTRANCE_LIMITS[area_id]
        if len(shop_entrances) > limit:
            errors.append(f"R5: {area_id} 入口数 {len(shop_entrances)} > 上限 {limit}")
    
    # R6: 每个 zone 至少有一条 segment 连接
    for zone in zones:
        if zone.parent_area != "":
            continue
        connected = any(
            s.from_zone == zone.zone_id or s.to_zone == zone.zone_id
            for s in segments if s.area_id == zone.area_id
        )
        if not connected:
            errors.append(f"R6: {zone.zone_id} 无道路连接")
    
    return errors
```

### 3.2 空气墙检查

```python
def audit_air_walls(colliders, zones, doors):
    errors = []
    for col in colliders:
        if col.kind != "air_wall":
            continue
        # C1: 空气墙必须与 zone 边界交集非空
        zone = find_zone(zones, col.area_id, col.zone_id)
        if not rect_intersects(col, zone, inclusive=True):
            errors.append(f"C1: {col.collider_id} 不在 zone 边界上")
        # C2: 空气墙不得阻断门
        for door in doors:
            if door.from_area == col.area_id and rect_intersects(col, build_door_rect(door)):
                errors.append(f"C2: {col.collider_id} 阻断 {door.door_id}")
    return errors
```

### 3.3 退出码

- `0`：全部通过
- `1`：几何错误（R1-R6）
- `2`：空气墙错误（C1-C2）

```gdscript
const MIGRATION_V14_TO_V15 := {
    "street": {
        "interact_home_1": {"area": "residential", "door": "door_res_home_1", "spawn": "home_default"},
        "interact_breakfast_1": {"area": "breakfast_street", "door": "door_breakfast_shop_1", "spawn": "shop_entrance"},
        "interact_clothing_1": {"area": "commercial_district", "door": "door_commercial_clothing_1", "spawn": "shop_entrance"},
        "interact_factory_1": {"area": "industrial_district", "door": "door_industrial_factory_1", "spawn": "factory_entrance"},
        "interact_recycle_1": {"area": "market", "door": "door_market_recycle_1", "spawn": "recycle_entrance"},
        "default": {"area": "residential", "door": "door_res_home_1", "spawn": "home_default"},
    }
}

func _migrate_v14_to_v15(data: Dictionary) -> Dictionary:
    var old_area: String = data.get("current_area", "street")
    var old_interaction: String = data.get("interaction_id", "default")
    var mapping: Dictionary = MIGRATION_V14_TO_V15.get(old_area, {})
    var target: Dictionary = mapping.get(old_interaction, mapping.get("default", {}))
    if target.is_empty():
        push_warning("无法迁移存档：area=%s interaction=%s" % [old_area, old_interaction])
        target = {"area": "residential", "door": "door_res_home_1", "spawn": "home_default"}
    data["current_area"] = target.area
    data["door_id"] = target.door
    data["spawn_id"] = target.spawn
    data["schema_version"] = 15
    return data
```

## 独立方案

# 独立方案：多场景城区合理分区与入口密度

> 独立方案 Agent 输出。**不迎合主方案**。本方案对 world-001（连续流式加载）与 world-002（分区审计）持**批判性继承**立场：承认其数据修复价值，但**拒绝其"单张 2560×1440 连续大地图 + chunk 流式"的架构前提**，因为该前提与"把过度堆叠的店面拆到多个连贯场景"这一任务目标**方向相反**——它把一切压进一张图，本任务要求把一切拆开。
>
> 本方案的核心主张：**用"场景图（Scene Graph）+ 门配对（Door Pairing）+ 入口预算（Entrance Budget）"三件套替代"连续大地图 + 空气墙审计"**。这是更高效、更可测、更兼容现有存档的实现路径。

## 一、与主方案的根本分歧（先说清楚，再给方案）

| 维度 | 主方案（world-001/002 路线） | **本独立方案** | 裁决理由 |
|---|---|---|---|
| 世界模型 | 单张 2560×1440 连续地图，chunk 流式加载 | **多场景节点图**，每个场景独立坐标系，门配对连接 | 任务原文是"拆到多个连贯场景"，不是"压进一张图"；连续大地图让"拆"变成"画得更散"，没有解决堆叠 |
| 场景边界 | 矩形 zone 拼接，断言无重叠无空洞 | **场景即节点**，边界是场景自身的画布边界，无需拼接断言 | 消除 P0-1/P0-5/P0-8~10 全部拓扑硬伤——它们只在"连续地图"假设下存在 |
| 入口密度控制 | 靠 `doors.csv` + 审计器事后检查 | **入口预算在场景定义期硬约束**，超预算直接拒绝加载 | 事后审计是补救，事前预算是预防 |
| 存档兼容 | 存 `world_pos`，需迁移坐标 | **存 `(area_id, spawn_id, local_pos)`**，与现有 `GameState.current_area/spawn_id` 完全一致 | 现有存档字段不变，零迁移成本 |
| 实现成本 | 需新建 WorldGraph autoload、chunk 管理器、LRU 驱逐、backdrop 裁剪 | **复用现有 `SceneRouter.travel_to` + `world.gd._build_area`**，只改数据表 | 现有代码已支持 34 个 area_id 的切换，架构已就位 |

**一句话**：主方案在造一台新引擎，本方案在**把现有引擎的数据表改对**。

### 3.2 入口预算的强制机制

```gdscript
# scripts/gameplay/area_backdrop.gd 新增
const ENTRANCE_BUDGET := {
    "residence": {"business": 4, "decor": 6},
    "breakfast_street": {"business": 6, "decor": 4},
    "commercial_district": {"business": 8, "decor": 6},
    "industrial_district": {"business": 5, "decor": 4},
    "market": {"business": 7, "decor": 5},
    "riverside": {"business": 3, "decor": 8},
    "nature": {"business": 2, "decor": 10},
}

func _register_interactable(node: WorldInteractable, category: String) -> bool:
    var budget: Dictionary = ENTRANCE_BUDGET.get(GameState.current_area, {})
    var limit: int = budget.get(category, 0)
    var current: int = _interactable_counts.get(category, 0)
    if current >= limit:
        push_error("[入口预算超限] %s 的 %s 入口已达上限 %d，拒绝注册：%s" % [
            GameState.current_area, category, limit, node.name
        ])
        return false
    _interactable_counts[category] = current + 1
    return true
```

**关键**：超预算时 `push_error` 并**拒绝注册**，而非静默通过。这比 world-002 的事后审计更早暴露问题。

## 四、区域边界（场景内布局规范）

### 4.1 场景画布尺寸统一为 1280×720

**理由**：
- 现有 `world.gd` 的 `CITY_MAP_SIZE = Vector2(2560, 1440)` 是**连续地图**假设下的产物，多场景架构下每个场景独立，无需 2560×1440。
- 1280×720 是 16:9，与主流分辨率匹配，缩放无黑边。
- 1280/16 = 80，720/16 = 45，**完美对齐 16px 网格**（art-001 的网格约束）。
- 单场景绘制调用量可控，无需 chunk 裁剪（消除 world-001 P0-3 硬伤）。

### 4.2 场景内分区（以商业区为例）

```

│  y=0                                         │
│  ┌────────────────────────────────────────┐  │

│  │  320)    │  │              │  │ 服务   │  │

## 五、道路连接（场景间动线）

### 5.1 道路类型与通行规则

| 道路类型 | 连接场景 | 通行时间 | 视觉表现 |
|---|---|---|---|
| 主干道 | 居住↔早餐↔商业↔工业 | 即时（门配对） | 宽路，有公交站 |
| 支路 | 市场↔各一级场景 | 即时 | 窄路，有摊位 |
| 步道 | 河畔↔自然 | 即时 | 石板路，有长椅 |
| 中转 | 任意↔transit_hub | 即时 | 公交/地铁图标 |

**关键决策**：**所有场景切换都是即时门配对，无"走路过渡"**。理由：
- 现有 `SceneRouter.travel_to` 是即时切换，加过渡动画会破坏存档兼容（需记录过渡状态）。
- "温柔治愈"风格下，即时切换 + 淡入淡出比"走路"更符合节奏。
- 避免 world-001 的 chunk 流式加载复杂度。

### 6.2 门配对的三条不变量

1. **对称性**：若 `A.door_x → B.door_y`，则 `B.door_y → A.door_x` 必须存在。审计器强制检查。
2. **唯一性**：一个 `door_id` 只能出现在一行。`target_door` 必须指向存在的 `door_id`。
3. **方向性**：`orientation` 为 `ns`（南北向门，玩家从左右进入）或 `ew`（东西向门，玩家从上下进入）。`offset` 是门在边上的位置（沿边距离）。

    var door_data := DoorRegistry.get_door(door_id)

# tools/audit_doors.py
def audit_doors():
    doors = load_csv("data/doors.csv")
    errors = []
    # A1: 对称性
    for d in doors:
        reverse = find_door(doors, d.target_area, d.target_door)
        if reverse is None:
            errors.append(f"A1 门 {d.door_id} 无反向门")
        elif reverse.target_door != d.door_id:
            errors.append(f"A1 门 {d.door_id} 反向门不匹配")
    # A2: 唯一性
    ids = [d.door_id for d in doors]
    if len(ids) != len(set(ids)):
        errors.append("A2 door_id 重复")
    # A3: 方向性
    for d in doors:
        if d.orientation not in ("ns", "ew"):
            errors.append(f"A3 门 {d.door_id} orientation 非法")
    # A4: 目标存在
    for d in doors:
        if d.target_area not in VALID_AREAS:
            errors.append(f"A4 门 {d.door_id} 目标区域不存在")
    return errors
```

## 1. 主方案（world-002 路线）的致命缺陷

### P0-1 场景数量与任务要求不符（硬伤）

**证据**：主方案 §1.2 声称拆为 7 个场景，但 `scene_zones.csv` 实际只有 **6 个 outdoor area_id**：`residential / breakfast_street / commercial_district / industrial_district / market / riverside / nature` —— 数一下是 **7 个**，但 §4.1 场景关系图只画了 **6 个节点**（nature→riverside→market→residential→breakfast_street→commercial_district→industrial_district），**market 与 riverside 之间的 `seg_riverside_market` 在 §4.2 表中存在，但 §4.1 图里没有这条边**。

**返工要求**：
- 重画 §4.1 关系图，必须包含 §4.2 表中**全部 7 条 segment**。
- 断言：`len(segments) == len(set((s.from_area, s.to_area) for s in segments))`，且每条 segment 的两个 area 都在 §1.2 表中。
- 断言：关系图邻接矩阵的边数 == `len(segments)`。

### P0-2 存档迁移表覆盖不全（数据丢失风险）

**证据**：§6.2 迁移表只有 **6 行**，全部 `old_area=street`。但 §1.1 诊断说 `street` 挂了 **9 个 zone**（market/village/nature/commercial_shops/commercial_services/industrial/suburb/center/activity）。迁移表只覆盖了 `interact_home_1 / interact_breakfast_1 / interact_clothing_1 / interact_factory_1 / interact_recycle_1 / default` 六个 `interaction_id`。

**缺失**：`street.nature`、`street.suburb`、`street.center`、`street.activity`、`street.commercial_services` 对应的旧 `interaction_id` **完全没有映射**。玩家若存档在 `street.nature` 区域，迁移后会被 fallback 到 `residential`（§6.4 代码 `target = {"area": "residential", ...}`），**位置错乱**。

**返工要求**：
- 从 git 历史或现有 `scene_zones.csv` 提取 `street` 下**全部** zone 的 `interaction_id` 清单。
- 迁移表必须**逐条覆盖**，断言：`set(old_interaction_ids) == set(migration.old_interaction_id)`。
- 新增审计：`tools/audit_save_migration.py` 检查 `len(migration) >= len(old_interactions)`。
- fallback 不能静默到 `residential`，必须 `push_error` 并**拒绝加载**（让玩家看到明确错误，而非位置错乱）。

### P0-3 门配对表与 doors.csv 不一致（死数据）

**证据**：
- §2.2 `doors.csv` 示例只有 **8 行**，且 `door_res_village_to_market` 的 `to_zone=old_market`，但 §5.2 门配对表里 `door_res_village_to_market` 的 `to` 是 `market.old_market` —— 一致。
- 但 §5.2 表有 **22 行**，§2.2 只给了 8 行示例。**§5.2 的 22 行没有对应的 CSV 内容**，无法验证。

## A. 主方案（world-002 路线）的致命问题

### A1. 数据自相矛盾，方案无法执行

**A1.1 `scene_zones.csv` 与"并集 == 2560×1440"断言直接冲突**

§2.1 给出的 zone 矩形，逐格扫描后**必然留空洞**。举证：

- `residential.village` = (60,880,620,520) → x∈[60,680], y∈[880,1400]
- `residential.suburb` = (2000,900,500,440) → x∈[2000,2500], y∈[900,1340]
- 两者之间 x∈(680,2000) 的 y∈[880,1400] 区域**无任何 zone 覆盖**
- `nature.park` = (850,900,650,500) 与 `residential.village` 在 x∈[850,680]？不，village 到 x=680 止，park 从 x=850 起，**x∈(680,850) 是空洞**

§3.1 R2 断言"所有 zone 并集 == map_size，无空洞"，但 §2.1 的数据**根本填不满**。审计器一跑就退出码 1。**方案在第一步就自毁**。

**A1.2 `breakfast_street` 三个 zone 的 x 全为 1500，w 全为 620**

- `breakfast_main` = (1500,900,620,210) → y∈[900,1110]
- `breakfast_kitchen` = (1500,1120,620,200) → y∈[1120,1320]
- `breakfast_stall` = (1500,700,620,180) → y∈[700,880]

`breakfast_main` 与 `breakfast_stall` 之间 y∈(880,900) 有 20px 空隙。R1 用 `<=` 判定"相邻不算重叠"，但 R2 要求无空洞——**20px 空隙就是空洞**。要么 R1 的 `<=` 判定错，要么 R2 的"无空洞"错，二者不可同时成立。

**A1.3 `commercial_district` 五个 zone 的 y 区间断裂**

- `north_shops` y∈[170,350]
- `west_housing` y∈[320,650] → 与 north_shops 在 y∈[320,350] **重叠**（x∈[60,320] vs x∈[60,1220]，重叠）
- `center_public` y∈[390,690]，与 west_housing 在 y∈[390,650] 且 x∈[440,700] vs x∈[60,320] **不重叠**，但 y∈[350,390] 是空洞
- `south_transit` y∈[590,690]，与 center_public 在 y∈[590,690] 且 x∈[600,1120] vs x∈[440,840] **重叠**

R1 会报 `north_shops` 与 `west_housing` 重叠、`center_public` 与 `south_transit` 重叠。**方案给出的数据通不过自己的审计器**。

### A2. 门配对数据与场景数据不一致

**A2.1 `door_res_village_to_market` 坐标 (680,900) 不在任何 zone 边界上**

- `residential.village` 右边界 x=680，y∈[880,1400] ✓ 在边界上
- 但 `market.old_market` = (250,300,500,320) → x∈[250,750], y∈[300,620]。**y=900 不在 old_market 内**
- 门声称 `to_area=market, to_zone=old_market`，但目标 zone 的 y 范围是 [300,620]，门在 y=900。**门指向场景外**

**A2.2 `door_riverside_to_nature` 坐标 (900,200) 与 `door_nature_to_riverside` 坐标 (850,1000) 不互逆**

- A→B 门在 (900,200)，B→A 门在 (850,1000)。**两个门不在同一位置**，玩家从 riverside 走到 nature 后，无法从 nature 的同一位置走回 riverside

### A3. 入口密度上限与数据冲突

**A3.1 §1.2 说 `commercial_district` 入口上限 5，但 §2.1 的 `commercial_district` 有 5 个 zone，每个 zone 至少 1 个店铺门**

- `west_housing`（置业与社区服务）→ 至少 1 门
- `center_public`（公共服务）→ 至少 1 门
- `east_living`（生活服务）→ 至少 1 门
- `south_transit`（交通）→ 0 门（合理）

**4 个经营门 + 1 个场景间门 = 5，刚好卡上限**。但 §5.2 只列了 `door_commercial_clothing_1` 一个店铺门。**其余 3 个 zone 的店铺门缺失**，方案未给出。若补上，入口数 = 4 店铺 + 1 场景间 = 5，**无余量**。§5.1 表格写"当前店铺门数 1，余量 4"是**错误统计**——它只数了 §5.2 列出的门，没数 §2.1 要求的门。

**A3.2 `residential` 入口上限 3，但 §2.1 有 3 个 zone（village/suburb/home_block），§5.2 只列 1 个店铺门**

## 四、入口密度机制（双层预算）

### 4.1 场景级预算（运行时强制）

```gdscript
# scripts/gameplay/area_backdrop.gd
const ENTRANCE_BUDGET := {
    "residence": {"business": 4, "decor": 6},
    "breakfast_street": {"business": 6, "decor": 4},
    "commercial_district": {"business": 8, "decor": 6},
    "industrial_district": {"business": 5, "decor": 4},
    "market": {"business": 7, "decor": 5},
    "riverside": {"business": 3, "decor": 8},
    "nature": {"business": 2, "decor": 10},
    "transit_hub": {"business": 0, "decor": 4},
    "suburb": {"business": 1, "decor": 3},
    "ruins": {"business": 0, "decor": 3},
}

var _interactable_counts: Dictionary = {}

func register_interactable(node: WorldInteractable) -> bool:
    var area := GameState.current_area
    var budget: Dictionary = ENTRANCE_BUDGET.get(area, {})
    var category := node.category  # "business" or "decor"
    var limit: int = budget.get(category, 0)
    var current: int = _interactable_counts.get(category, 0)
    if current >= limit:
        push_error("[入口预算超限] %s/%s 已达上限 %d，拒绝注册：%s" % [area, category, limit, node.name])
        return false
    _interactable_counts[category] = current + 1
    if current + 1 >= limit * 0.8:
        push_warning("[入口预算警告] %s/%s 接近上限 %d" % [area, category, limit])
    return true
```

**批判闭环**：
- **P1-2（无调用点）**：`WorldInteractable._ready()` **强制**调用 `register_interactable(self)`，审计器 `grep` 验证至少 1 个调用点。
- **P1-8（category 无定义）**：`WorldInteractable` 新增 `@export var category: String = "decor"`，审计器验证取值。
- **P2-4（无视觉反馈）**：80% 时 `push_warning`，100% 时 `push_error` + debug UI 黄色/红色警告。

### 4.2 子区级预算（CI 审计）

`scene_layout.csv` 的 `entrance_budget_business` / `entrance_budget_decor` 列，审计器 B1 检查：
- 每个子区预算 ≤ 场景级预算
- 所有子区预算之和 ≤ 场景级预算

**批判闭环**：
- **B3.2（双轨预算）**：明确**场景级是运行时强制，子区级是 CI 审计**，二者由审计器 B1 强制一致。

### 6.2 `door_trigger.gd`（批判A P1-7 闭环）

```gdscript
# scripts/gameplay/door_trigger.gd
class_name DoorTrigger
extends Area2D

@export var door_id: String

func _ready() -> void:
    var door_data := DoorRegistry.get_door(door_id)
    if door_data.is_empty():
        push_error("[门配对] 未知 door_id: %s" % door_id)
        return
    # 碰撞层：门层 = 0b1000，玩家层 = 0b0001
    collision_layer = 0b1000
    collision_mask = 0b0001
    monitoring = true
    monitorable = false
    # 创建碰撞形状
    var shape := CollisionShape2D.new()
    var rect := RectangleShape2D.new()
    rect.size = Vector2(door_data.door_w, door_data.door_h)
    shape.shape = rect
    shape.position = Vector2(door_data.door_x, door_data.door_y)
    add_child(shape)
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node2D) -> void:
    if not body.is_in_group("player"):
        return
    var door_data := DoorRegistry.get_door(door_id)
    SceneRouter.travel_to(door_data.target_area, door_data.spawn_id)
```

### 6.3 存档迁移（批判A P0-2、P2-5 闭环）

```gdscript
# autoload/save_manager.gd
const MIGRATION_TABLE := "res://data/save_migration_v1_to_v2.csv"

func load_save(path: String) -> Dictionary:
    var data := _read_save(path)
    var version: int = data.get("schema_version", 1)
    if version >= 2:
        return data
    # 备份
    _backup_save(path)
    var migrated := _migrate_v1_to_v2(data)
    if migrated.is_empty():
        _restore_save(path)
        push_error("[存档迁移] 迁移失败，已回滚")
        return {}
    _write_save(path, migrated)
    return migrated

func _migrate_v1_to_v2(data: Dictionary) -> Dictionary:
    var old_area: String = data.get("current_area", "")
    var old_spawn: String = data.get("spawn_id", "default")
    var old_interaction: String = data.get("interaction_id", "")
    var key := "%s|%s|%s" % [old_area, old_spawn, old_interaction]
    var migration := _load_migration_table()
    if not migration.has(key):
        # 尝试只用 area|spawn
        key = "%s|%s|" % [old_area, old_spawn]
        if not migration.has(key):
            push_error("[存档迁移] 未命中映射：%s" % key)
            return {}  # 拒绝加载，触发回滚
    var row: Dictionary = migration[key]
    data["current_area"] = row.new_area
    data["spawn_id"] = row.new_spawn
    data["door_id"] = row.new_door_id
    data["local_pos"] = _parse_position(row.fallback_position)
    data["schema_version"] = 2
    return data
```

**批判闭环**：
- **P0-2（迁移表覆盖不全）**：未命中时**拒绝加载 + 回滚**，不静默 fallback。
- **P2-5（无回滚）**：迁移前备份，失败时恢复。
- **B4.3（save_version 检测）**：`schema_version` 缺失时默认 1。
