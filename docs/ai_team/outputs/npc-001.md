# 下一批常驻 NPC 与限时 NPC

## 多 Agent 主方案

## 1. 现状判断

现有 17 位 NPC 已覆盖：出租屋/邻里、工厂、便利店、旧货、早餐、服装、河边、周末帮工、节日摊、校园兼职、物流夜班、市场管理、公交、医疗、房产、快递、夜校。**尚未覆盖的空白**：餐饮正餐/夜宵摊主、理发/修理类手艺人、社区行政/证件类、宠物相关、图书馆/档案类、码头/货运以外的水域作业者、以及“限时但非节日”的短期 NPC（如短期驻场、临时项目、季节工）。

现有 NPC 中 `xiaoyu`、`lan` 已是限时型，新限时 NPC 需在**触发维度**上区分（非节日、非周末，而是“项目/季节/事件”驱动）。

## 4. 实施步骤

1. 在 `npcs.csv` 末尾追加 6 位 NPC，`npc_id` 使用 `song/liang/cai/ahui/qu/ji`，避免与现有冲突。
2. 在 `npc_schedule.csv` 追加日程，坐标沿用对应城区已有 NPC 的 `pos_x/pos_y` 附近值，避免重叠。
3. 在 `npc_dialogue.csv` 按 `morning/noon/evening` 各补 2–3 条，`min_affinity` 分层 0/4/10。
4. 在 `npc_stories.csv` 追加 3+3+3+3+2+2 条剧情，`required_flag` 复用现有 flag（`employed/housing_upgraded/family/pet_adopted/photo_taken/collection_10/business_owned/promoted/travel/fish_caught/riverside_visited/commute_used`）。
5. 在调度解析层新增 `season:` 与 `event:` 前缀支持；若暂不支持，先以 `always` 占位并在 `open_questions` 记录。
6. 更新共享黑板 `decisions`，记录“新增 6 NPC 及 condition 扩展”。

## 5. 验证方法

- **数据完整性**：6 个 `npc_id` 在 4 个 CSV 中均有记录，无孤儿行。
- **时间冲突**：同一 NPC 日程无重叠时段；同一区域同一时段 NPC 坐标不重叠。
- **flag 可达性**：所有 `required_flag` 均已在现有 `npc_stories.csv` 中出现过。
- **限时触发**：`season:summer` 与 `event:city_festival_week` 在测试环境手动切换后 NPC 正确出现/消失。
- **提示分离**：新 NPC 对话不包含数值、不包含未解锁系统名（如“宠物系统”“活动周系统”）。
- **存档兼容**：旧存档加载后新 NPC 按默认 affinity 0 出现，不报错。

## 6. 风险与回退

| 风险 | 回退 |
|---|---|
| `season:`/`event:` condition 解析未实现 | 先以 `always` 上线，NPC 常驻，后续补 condition |
| 新 NPC 坐标与现有重叠 | 回退到该城区已有 NPC 坐标 + 偏移 40px |
| flag 拼写错误导致剧情不可触发 | 对照现有 `npc_stories.csv` 逐条校验 |
| 限时 NPC 与 `lan`/`xiaoyu` 触发条件混淆 | 明确 `qu` 用季节、`ji` 用事件，与节日/周末区分 |
| 存档中已存在同名 `npc_id` | 上线前全量扫描 `npc_id` 唯一性 |

# 1. 现状判断

- 现有 17 位 NPC 已覆盖：房东/邻里、工厂、便利店、旧货、早餐、服装、河边、节日、校园兼职、物流夜班、市场管理、公交、医疗、房产、快递、夜校。

- 现有日程全部 `always` 或简单 `weekend/festival`，缺少**天气驱动**和**季节驱动**的常驻 NPC 日程。
