**FLUX prompt**：
```
Top-down 2.5D pixel art city overview map, 2560x1440, 16px grid aligned,
a gentle riverside city in late afternoon, low-saturation warm palette,
misty blue-grey rooftops (#8B9BA8), warm sand-colored streets (#C4A882),
brick-orange accents on a few buildings (#D97E60), soft diffused sunlight,

industrial edge in the lower right, no neon signs, no cyberpunk,

```

**验收标准**：
1. 分辨率严格 2560x1440，PNG 无损
2. 建筑边缘落在 16px 网格（用 `tools/verify_grid.py` 抽样 20 个边缘点，误差 ≤1px）

4. 无纯黑（#000000）像素，最暗色 ≥ #1A1A1A
5. 无纯白（#FFFFFF）像素，最亮色 ≤ #F0E8D8
6. 无霓虹色（饱和度 > 80% 且亮度 > 70% 的像素占比 < 0.5%）
7. 缩放到 640x360 后仍能辨认 4 个分区（人工目检）

**接入路径**：
- 文件：`assets/art/formal/scenes/city_overview/background.png`

- 场景注册：`data/scene_metadata.csv` 新增 `city_overview`，`SceneRouter.VALID_AREAS` 加入

# 独立方案：正式资产母版清单与 FLUX 生成 Prompt

> 立场声明：本方案不沿用主方案"逐场景补图"的路线。主方案倾向按 `scene_metadata.csv` 逐条补背景，收益递减且无法解决**跨场景一致性**。本方案改为**母版（Master Sheet）驱动**：先定 6 张母版（城市/商业/工业/生活/UI/物品），所有具体资产从母版派生。任何新场景先问"它属于哪张母版"，再决定是否新增。

## 一、架构差异（与主方案的分歧点）

| 维度 | 主方案倾向 | 本方案 |
|---|---|---|
| 组织方式 | 按 scene_id 逐张补 | 按 **母版（Master）** 分组，母版内共享色板/光位/材质 |
| Prompt 结构 | 单场景描述 | **母版前缀 + 场景后缀** 两段式，前缀锁定画风 |

# 批判报告：两份方案的遗漏、冲突、死代码与返工要求

## A. 致命冲突（必须先裁决，否则无法开工）

### A1. 分辨率规范直接对撞，且两份都无依据
- 主方案：城市 2560×1440、室内 1280×720、NPC world 32×48、portrait 128×128、item 32×32。
- 独立方案：场景 1920×1080、item 32×32、母版 2048×512 / 1024×1024 / 256×256。
- **两份都没有引用任何现有代码/数据作为分辨率来源**。`generate_pixel_art.py` 的 `SCENE_PALETTES` 只给色板，不给尺寸；`visual_bindings.csv` 现有 3 个场景的实际 PNG 尺寸未被任何一方读取。
- **返工要求**：先跑一条命令把现有 formal 与 fallback 资产的实际尺寸 dump 出来，作为唯一事实源：
  ```bash
  python -c "from PIL import Image; import glob,os; [print(p, Image.open(p).size) for p in glob.glob('assets/art/formal/**/*.png',recursive=True)]"
  ```
  在拿到真实尺寸前，两份方案的所有尺寸断言都是**不可验证的**，验收标准第 1 条（"严格 2560×1440"）属于**死断言**。

### A2. 网格规范自相矛盾
- 主方案 1.3 说"16px 网格"，但 2.1 验收标准 2 说"建筑边缘落在 16px 网格，误差 ≤1px"。
- **16px 网格 + ≤1px 误差 = 逻辑矛盾**：若网格是 16px，边缘要么在 16 的倍数（误差 0），要么不在。≤1px 容差意味着允许 15~17px 的偏移，这已经不是 16px 网格。
- 更严重：`tools/verify_grid.py` 被引用为验收工具，但**该文件在交付物清单里不存在**，也没说明是否已存在。这是**引用死代码**。
- **返工要求**：明确网格定义（"边缘坐标 mod 16 ∈ {0}" 还是 "边缘落在 16px 网格线的 ±1px 带内"），并确认 `verify_grid.py` 是否存在；不存在则列入交付物。

### A3. 母版路线与覆盖层机制冲突（独立方案的核心缺陷）
- 独立方案说"`PresentationManager.get_resolved_asset_path()` 逻辑不变，只多读 `master_ref` 用于回退链：具体资产缺失 → 母版对应 panel → 程序化基线"。
- **但主方案 2.1 明确写了回退是"formal 缺失 → `generate_pixel_art.py` 生成的 fallback"**。两份对回退链的定义不同。
- 独立方案要求"母版对应 panel"作为回退，意味着 `get_resolved_asset_path()` **必须改代码**（要读 `asset_masters.csv`、要按 panel 裁切）。这与"逻辑不变"直接矛盾。
- **返工要求**：独立方案必须给出 `get_resolved_asset_path()` 的**伪代码 diff**，证明"逻辑不变"如何实现 panel 裁切回退。做不到就承认要改代码，并列出改动点与回归测试。

### A4. 母版作为 img2img 参考图 = 未验证的机制
- 独立方案四.1："从母版裁切对应 panel 作为 FLUX img2img 参考图（strength=0.35）"。
- **没有任何证据表明 FLUX 支持 img2img 且 strength 参数可用**。主方案全程用 text2img。独立方案把整个派生流程押在一个未验证的 API 能力上。
- **返工要求**：先做一次 spike——用一张母版 panel 跑一次 img2img，确认：(a) 工具链支持；(b) strength=0.35 的实际效果；(c) 输出尺寸可控。spike 失败则独立方案的"3 分钟派生"收益归零，需回退到 text2img + 母版色板约束。

### D2. 色板校验的 ΔE 阈值无依据
- 独立方案六节：色板一致性 ΔE < 15。
- **ΔE < 15 在 CIELAB 空间是"肉眼可辨差异"**，对"风格统一"来说太松。且没说用 ΔE76 还是 ΔE2000。
- 主方案 4.3 验收标准 3："色相差 ≤30°"——**色相差 30° 是很大的差异**（红→橙→黄），不足以保证"同色系"。

### D3. "无纯黑/纯白"断言不可靠
- 两份都要求"无纯黑 #000000、无纯白 #FFFFFF"。
- **但 PNG 可能有 alpha 通道，透明区域的 RGB 可能是 0,0,0**。直接统计 RGB 会把透明像素误判为纯黑。
- **返工要求**：断言必须排除 alpha=0 的像素：
  ```python
  px = [p for p in img.getdata() if p[3] > 0]
  assert all(p[:3] != (0,0,0) for p in px)
  ```

## 5. 验收标准（可脚本化，修正批判 D）

### 5.1 统一校验脚本 `tools/verify_art.py`
**合并 `verify_grid.py`（R3）**，单一入口，参数 `--asset <path> --type <scene|npc|item|ui>`。

| 检查 | 方法 | 阈值 | 失败 |
|---|---|---|---|
| 尺寸 | `Image.size` 精确匹配 §2.3 | 精确 | 拒绝 |
| 网格 | 边缘坐标 `mod 16 == 0`，容差 0 | 精确 | 拒绝 |
| 色板 | CIEDE2000 ΔE，与母版主色比 | **ΔE2000 < 8** | 拒绝 |
| 饱和度 | HSV S 通道 95 分位 | **S < 0.55** | 拒绝 |
| 光位 | Sobel 梯度主方向 | upper-left 象限 ±30° | 警告 |
| 无纯黑/纯白 | **排除 alpha=0 像素**（D3） | 精确 | 拒绝 |
| 透明边距 | 物品四周 2px alpha=0 | 精确 | 拒绝 |

**ΔE 阈值依据（R14）**：用现有 3 个已批准资产（home/street/riverside）做基线，取其两两 ΔE2000 的 90 分位作为阈值。若基线 ΔE2000 > 8，则阈值放宽到基线值。

**无纯黑/纯白断言（R15）**：
```python
px = [p for p in img.convert("RGBA").getdata() if p[3] > 0]
assert all(p[:3] != (0,0,0) for p in px), "纯黑像素"
assert all(p[:3] != (255,255,255) for p in px), "纯白像素"
```

### 5.2 人工验收（每母版一次，不逐张）
- 母版内资产并排看，色温/光位/材质统一。
- 与上一母版对比，属同一世界。
- 缩到 25% 看剪影可读。

### 5.3 门禁脚本 `tools/affected_tests.py`（R13）
输入改动的资产/CSV，输出应跑门禁：
```python
RULES = {
    "visual_bindings.csv": ["scene_gate", "save_gate"],
    "scene_metadata.csv": ["scene_gate", "save_gate"],
    "ui_assets.csv": ["ui_gate", "window_gate"],
    "items/*.png": ["economy_gate", "item_gate"],
    "scenes/*.png": ["scene_gate", "window_gate"],
    "characters/*.png": ["scene_gate", "window_gate"],
}
```

**各门禁定义**：
- `scene_gate`：跑分区、碰撞、出口测试。
- `save_gate`：加载旧存档 → 断言 `current_area` 可解析（R18）。
- `ui_gate`：跑 `PresentationManager.build_theme()` 缓存测试。
- `window_gate`（R16）：启动游戏 → 进入场景 → 截图 → 与 `tests/baseline/window/<scene_id>.png` 做像素 diff → 断言 diff < 2%。
- `economy_gate`（R17）：模拟"赠送 preferred_item → 好感度/货币变化" → 断言变化值在 npc-001 裁决范围内。
- `item_gate`：物品 icon 尺寸/边距校验。
