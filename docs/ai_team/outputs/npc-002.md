## 主方案

# 《深城日常》NPC 提示风格与三类提示边界 —— 可执行方案

> 目标：为现有 17 位 NPC 建立**性格 / 口癖 / 可靠度 / 提示范围**规范；明确 **NPC 提示 / 系统提示 / 场景提示** 的边界与 UI 呈现；给出对话数据字段与可直接实施的示例。
> 约束遵守：无任务面板、无数值属性条、场景点击经营、固定物价、存档兼容、温柔治愈画风。
> 不新增 NPC，不编造重复角色。所有示例基于 `data/npcs.csv` 现有 17 位。

## 1. 三类提示的定义与边界（唯一裁决）

### 1.1 定义

| 类别 | source_kind | 说话人 | 本质 | 触发者 |
|---|---|---|---|---|
| **NPC 提示** | `npc` | 具体 NPC 名（如"梅姨"） | 角色对玩家说的话，有性格、有口癖、有可靠度 | 玩家靠近/点击 NPC、NPC 主动搭话 |
| **系统提示** | `system` | 固定为"系统" | 游戏机制反馈，无角色人格 | 存档、读档、版本、设置、错误、成就解锁 |
| **场景提示** | `scene` | 场景显示名（如"老街"） | 环境/地点对玩家的描述，无人格 | 进入区域、天气变化、时段切换、场景交互物 |

### 1.2 边界裁决表（消除歧义）

| 情形 | 归属 | 理由 |
|---|---|---|
| 梅姨说"今天看着要降温" | NPC | 有说话人、有性格 |
| "已保存到存档 3" | 系统 | 机制反馈 |
| "老街的灯亮起来了" | 场景 | 环境描述，无具体说话人 |
| "你获得了 1 个饺子" | 系统 | 物品获取是机制 |
| 黄姐说"第一笼包子给你" | NPC | 有说话人 |
| "早餐时段已开始" | 场景 | 时段是环境状态 |
| "好感度 +1" | **禁止出现** | 违反"无数值属性条"约束，改为 NPC 台词暗示 |
| "任务：去工厂上班" | **禁止出现** | 违反"无任务面板"约束，改为 NPC 台词引导 |
| "体力不足，无法工作" | 系统 | 机制限制反馈（若体力系统存在） |
| 强叔说"看水色就知道今天风往哪边吹" | NPC | 有说话人 |
| "河边起雾了" | 场景 | 环境状态 |

### 1.3 优先级（用于 `ui-001` 的 `NoticeArbiter`）

```
system > npc > scene
```
- 同帧多提示时，高优先级抢占；低优先级入队等待。
- 同优先级同帧：按投递顺序，间隔 ≥ 350ms（沿用现有 `_emit_notice` 去重窗口）。
- **禁止**：NPC 提示与系统提示同帧同时显示（会混淆玩家对"谁在说话"的判断）。

## 2. NPC 性格 / 口癖 / 可靠度 / 提示范围规范

### 2.1 字段定义（写入 `data/npcs.csv` 新增列）

| 列名 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `voice_tone` | enum | 语气基调：`warm` / `blunt` / `calm` / `bright` / `dry` / `gentle` | `warm` |
| `speech_trait` | string | 口癖描述（用于写作参考，不直接显示） | `句尾常带"啊""吧"，爱用食物比喻` |
| `reliability` | enum | 可靠度：`high` / `medium` / `low` | `high` |
| `hint_scope` | string(分号分隔) | 提示范围标签，见 2.3 | `weather;home_life;neighbor` |
| `hint_ceiling` | enum | 提示上限：`daily` / `career` / `system_adjacent` | `daily` |
| `forbidden_topics` | string(分号分隔) | 禁止该 NPC 提及的话题 | `数值;任务;未解锁系统` |

**存档兼容**：新增列不影响现有存档（存档只存 `npc_id` + `affinity` + `flags`，不存 CSV 列）。

### 2.2 可靠度定义

| 等级 | 含义 | 玩家应感知 | 示例 NPC |
|---|---|---|---|
| `high` | 说的基本准确，可依赖 | "听他的没错" | 梅姨、王师傅、林医生、老许 |
| `medium` | 大方向对，细节可能偏差 | "参考一下" | 小林、阿珍、陈伯、黄姐、周姐、方姐、余老师 |
| `low` | 带主观色彩，可能夸张/记错 | "听听就好" | 小雨、阿榕、阿珂、小满 |

**可靠度不显示为数值**，通过台词措辞体现：
- `high`：陈述句为主，"今天要降温"。
- `medium`：带限定词，"我记得好像是……""大概"。
- `low`：带情绪/夸张，"超好看！""绝对！"

## 3. 对话数据字段规范

### 3.1 `data/npc_dialogue.csv` 现有字段（保留）

```
npc_id, period, line, weather, career_line, min_affinity
```

### 3.2 新增字段（追加列，不破坏现有行）

| 列名 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `hint_kind` | enum | `npc` / `scene`（默认 `npc`） | `npc` |
| `hint_scope` | string | 该条台词所属提示范围，须 ∈ 该 NPC 的 `hint_scope` | `weather` |
| `reliability_hint` | enum | 该条台词的可靠度，默认继承 NPC 的 `reliability` | `high` |
| `cooldown_sec` | int | 同条台词最短重复间隔（秒），默认 0 | `300` |
| `priority` | int | 同帧投递优先级，默认 0，越大越先 | `0` |
| `requires_flag` | string | 触发所需 flag（可选） | `employed` |
| `forbids_flag` | string | 有此 flag 时不触发（可选） | `business_owned` |

**存档兼容**：新增列只影响新读入的台词，旧存档不受影响。

### 3.3 字段取值规则

1. `hint_scope` 必须 ∈ 该 NPC 的 `hint_scope` 集合，否则加载时报错。
2. `reliability_hint` 不得高于 NPC 的 `reliability`（防止低可靠度 NPC 突然说准话）。
3. `cooldown_sec` 默认 0，但**天气/时段类台词建议 ≥ 300**，避免刷屏。
4. `priority` 仅用于同帧仲裁，日常台词一律 0。
5. `requires_flag` / `forbids_flag` 与 `npc_stories.csv` 的 `required_flag` 语义一致。

## 4. 投递规则与 `NoticeManager` 收敛

### 4.1 三类提示的投递入口（唯一）

```gdscript
# autoload/notice_manager.gd —— 保持现有 API，不新增
show_npc_message(message, speaker, tone)      # source_kind = "npc"
show_system_message(message, tone)            # source_kind = "system"
show_scene_message(message, source_label, tone) # source_kind = "scene"
```

**禁止**：任何脚本直接 `emit notice_requested`。所有提示必须走上述三个入口。

### 4.2 `get_speaker()` 收敛（修复 G0.4 的不一致）

现有 `get_speaker()` 的 `match area` 硬编码与 `npcs.csv` 不一致。裁决：

**改为从 `npcs.csv` 按 `home_area` 反查**：

```gdscript
func get_speaker(message: String = "", _tone: String = "normal", explicit_speaker: String = "", source_kind: String = "") -> String:
	if source_kind == "system":
		return "系统"
	if not explicit_speaker.is_empty():
		return explicit_speaker
	if source_kind == "scene":
		return str(PresentationManager.get_scene_metadata(GameState.current_area).get("display_name", "场景"))
	# NPC 提示：按当前区域反查 npcs.csv
	var area := GameState.current_area
	var npc := NpcManager.get_npc_by_home_area(area)
	if npc != null:
		return npc.name
	return "街坊"
```

**风险**：同一 `home_area` 有多个 NPC（如 `home` 有 mei、huang、xiaoman）。
**裁决**：`get_npc_by_home_area()` 返回**当前区域最近交互的 NPC**；若无交互记录，返回该区域 `home_area` 匹配的第一个（按 `npc_id` 排序）。**优先走 `show_npc_message` 显式传 speaker**，`get_speaker` 仅作兜底。

### 4.3 场景提示的 `source_label`

场景提示的说话人 = 场景显示名，从 `PresentationManager.get_scene_metadata(area).display_name` 取。
**禁止**：场景提示使用 NPC 名（会混淆玩家对"谁在说话"的判断）。

### 4.4 去重与冷却

- 现有 350ms 去重窗口保留。
- 新增 `cooldown_sec` 按 `npc_id + line` 维度记录，存于 `NpcManager` 内存（不存档）。
- 天气/时段切换时，清空对应 `hint_scope` 的冷却（允许新天气台词立即触发）。

## 5. UI 呈现规范

> 依赖 `ui-001` 的 `NoticeArbiter` 单通道。若未落地，本节标注 `[依赖 ui-001]`。

### 5.1 三类提示的视觉区分（不靠颜色区分，靠前缀/图标）

| 类别 | 前缀 | 图标 | 位置 | 时长 |
|---|---|---|---|---|
| NPC | 无前缀，直接显示 `speaker：line` | 无 | 屏幕中下 | 3.5s |
| 系统 | `[系统]` | 无 | 屏幕中下 | 2.5s |
| 场景 | 无前缀，直接显示 `line`（斜体） | 无 | 屏幕中下 | 3.0s |

**裁决**：
- **不用颜色区分**（违反低饱和暖色约束，且色盲不友好）。
- **用前缀 + 斜体**区分：系统带 `[系统]`，场景斜体，NPC 正常。
- 所有提示共用同一 `NoticeArbiter` 通道，按 §1.3 优先级仲裁。

### 5.2 字号与样式（走 `ui-001` 的 `ui_text_styles.csv`）

| 类别 | style_key | 说明 |
|---|---|---|
| NPC | `notice_npc` | 正常字重 |
| 系统 | `notice_system` | 正常字重 + `[系统]` 前缀 |
| 场景 | `notice_scene` | 斜体 |

**禁止**：在代码中硬编码字号/颜色，全部走 `ui_text_styles.csv`。

### 5.3 与 `ui-001` 的接口

- `NoticeArbiter.push(message, tone, speaker, source_kind)` 接收本方案的三类提示。
- `source_kind` 决定前缀与样式，`speaker` 决定是否显示说话人。
- **不新增 UI 节点**，复用现有提示渲染。

## 独立方案

# 独立方案：NPC 提示风格与三类提示边界

> 独立方案 Agent 输出。**不迎合主方案**。核心分歧点先摆明：
> 1. 主方案倾向"给每个 NPC 加 personality/口癖字段，运行时拼提示"——本方案**反对**。口癖不该是运行时字符串拼接，应是**数据表里的成品句**，运行时只做**选择**不做**生成**。
> 2. 主方案倾向"三类提示各建一个 Manager"——本方案**反对**。`notice_manager.gd` 已存在且已带 `source_kind` 分流，**扩展现有单通道**比新建三通道更省、更不易漏。
> 3. 主方案倾向"可靠度做成数值"——本方案**反对**。约束明确"无数值属性条"，可靠度必须是**离散枚举 + 行为可观察**，不是 0~100 的隐藏分。

## 一、先修现有代码的硬伤（阻塞项）

`autoload/notice_manager.gd` 当前有 4 个必须修的问题，否则三类边界无法落地：

### 硬伤 1：`infer_source_kind` 把一切非系统消息都判成 `npc`

```gdscript
func infer_source_kind(message: String, explicit_speaker: String = "") -> String:
	if not explicit_speaker.is_empty():
		return "npc"          # ← 场景提示只要带 speaker 就被误判为 npc
	if message.contains("存档") ...:
		return "system"
	return "npc"              # ← 兜底也是 npc，scene 永远进不来
```

**后果**：`show_scene_message("河边风大", "河边")` 会被判成 `npc`，UI 上顶着"河边"当人名显示。三类边界从源头就塌了。

**修法**：`infer_source_kind` 只做**兜底猜测**，且必须显式传 `source_kind`。所有调用点强制走 `show_npc_message` / `show_system_message` / `show_scene_message` 三个具名入口，禁止裸调 `show_message`。

### 硬伤 2：`get_speaker` 里硬编码了 20+ 个场景→人名映射

```gdscript
match area:
	"restaurant": return "厨房师傅"
	"breakfast_shop", "breakfast_kitchen": return "黄姐"
	...
```

**后果**：
- `restaurant` 场景在 world-001 里已确认**不存在**，这行是死代码。
- `pet_store` 返回"宠物店老板"，但 npc-001 已定 `ahui`（阿灰）是宠物店 NPC，**两处会打架**。
- 场景→NPC 的映射是**世界数据**，不该埋在提示管理器里。world-001 已确立 `scene_zones.csv` 为场景唯一真相源，NPC 归属应挂 `NodeContainer[node_id]`。

**修法**：删除整个 `match area` 块。speaker 由**调用方**显式传入（NPC 提示传 npc_id 对应的显示名，场景提示传场景 display_name）。`get_speaker` 只保留"system → 系统"一条规则。

### 硬伤 3：去重窗口 350ms 会吞掉合法的连续提示

```gdscript
if message == _last_message and now - _last_ticks < 350:
	return
```

**后果**：玩家连点两次同一交互物，第二次提示被吞。但"连点两次"本身是**有效输入**，不该静默丢弃。

**修法**：去重键改为 `message + source_kind + speaker`，窗口缩到 120ms（只挡同帧重复 emit），且**不吞**——改为"同键在窗口内则刷新计时器而非丢弃"。

### 硬伤 4：`show_message` 的 `source_kind` 默认空串，走 infer 兜底

**修法**：`show_message` 标记为 `@deprecated`，内部转调 `show_scene_message`（最保守的默认），并在编辑器里 `push_warning`。

## 二、三类提示的边界定义（唯一裁决）

| 维度 | NPC 提示 | 系统提示 | 场景提示 |
|---|---|---|---|
| **谁在说** | 有名字、有性格的 NPC | 游戏本身（无角色） | 地点/环境（无角色） |
| **触发源** | 玩家与 NPC 交互、NPC 主动搭话 | 存档/读档/版本/错误/设置变更 | 进入区域、天气变化、时段切换、点击环境物 |
| **口吻** | 第一人称，带口癖 | 中性、无主语或"系统" | 第三人称描述，无人称 |
| **可靠性** | 分三档（见 §3），可能不准 | 100% 准确 | 100% 准确但**不完整**（只描述现象） |
| **能否给建议** | 能，但可能带主观偏差 | 只陈述事实，不给建议 | 只描述现象，不给建议 |
| **UI 位置** | 左下对话气泡（带头像/名字） | 顶部居中横幅 | 屏幕中下方淡入淡出文字 |
| **UI 样式** | 暖色气泡，有 speaker 名 | 冷灰横幅，无 speaker | 无背景，仅文字+柔光 |
| **停留时长** | 4~6s（可点击关闭） | 3s（不可关闭） | 2.5s（自动淡出） |
| **是否入日志** | 是 | 是 | 否 |

### 边界裁决规则（写进代码注释，防后人越界）

1. **NPC 提示不得陈述系统事实**。梅姨不能说"存档成功"。若 NPC 要提存档，必须转成角色口吻："你刚才是不是把东西收好了？"——这仍是 NPC 提示，但**不承诺系统状态**。
2. **系统提示不得有 speaker 名**。`show_system_message` 强制 speaker="系统"，且 UI 不渲染头像。
3. **场景提示不得给建议**。可以"河边风大"，不可以"河边风大，建议加衣服"——后者是 NPC 或系统的事。
4. **同一事件只走一类通道**。进入河边触发场景提示"河面起了雾"；强叔此时若在场，是**独立的一次 NPC 交互**，不是场景提示的附属。

### 3.2 口癖：不运行时拼接，用成品句 + 选择器

**反对**主方案的"模板 + 变量替换"（如 `"{address}，今天{weather}，{advice}"`）。理由：

- 中文语序/语气词无法靠模板自然生成。

### 3.3 可靠度：三档离散枚举，行为可观察

**反对**数值可靠度。约束"无数值属性条"，且数值可靠度玩家看不见=无意义。

**采用三档**：

| 档位 | 含义 | 行为表现 | UI 表现 |
|---|---|---|---|
| `high` | 说的基本准 | 提示与后续事件一致率 ≥90% | 正常显示 |
| `medium` | 有时凭印象 | 一致率 60~90%，偶尔偏差 | 正常显示，但偏差时后续有"其实……"修正 |
| `low` | 爱联想/传话 | 一致率 <60%，常把课堂/传闻当事实 | 显示时加"听说"或"我猜"前缀 |

**可观察性设计**（这是本方案与主方案的核心差异）：

- `high` 档 NPC（梅姨、王师傅、陈伯、黄姐、强叔、阿森、周姐、老许、林医生、余老师）：提示**直接可用**。玩家按提示做，结果符合预期。
- `medium` 档（小林、阿珍、小雨、方姐、阿珂）：提示**方向对但细节可能偏**。如小林说"晚点来看看新货"，实际新货可能明天才到——玩家来了发现没有，小林会说"哎呀记错了，明天准到"。**这个"记错"是预设的，不是 bug**。
- `low` 档（小满）：提示**是她的联想，不是事实**。小满说"我同学说河边晚上有萤火虫"，去了可能没有。玩家不会觉得被骗，因为小满的人设就是"把课堂问题带到街上"。

**实现**：`reliability` 只影响**写手写句时的约束**和**校验器检查**，不影响运行时逻辑。运行时**不做概率判定**——每句提示的准确性在数据层就定死了（`reliability_hint` 列）。这样：
- 可测试：给定 npc_id + 情境，输出确定。
- 可审查：写手写 `low` 档 NPC 的句子时，校验器强制加"听说/我猜/好像"。
- 无隐藏数值：玩家通过**多次交互**自然感知谁靠谱，符合"温柔治愈"（不惩罚，只是有性格）。

## 五、选择器算法（纯函数，可单测）

### 5.1 `NpcVoiceSelector.pick`

```
输入：npc_id, period, weather, career_line, affinity, context_tags[]
1. 过滤 npc_dialogue 中 npc_id 匹配的行
2. 过滤 period 匹配（或 period 为空=通用）
3. 过滤 weather 匹配（或为空=通用）
4. 过滤 min_affinity <= 当前 affinity
5. 过滤 career_line 匹配（或为空=通用）
6. 若 context_tags 非空，按 tone_tag 交集排序，取交集最大者
7. 同分时按 (period 具体 > 通用) > (weather 具体 > 通用) > 行序 排序
8. 返回首行；若全被过滤，回退到 period 通用行；再无则返回空
```

**只选不拼**。返回的 `line` 直接显示，最多按 `reliability_hint` 加前缀：
- `空`：正常显示。
- `guess`：加"大概"前缀。
- `uncertain`：加"听说"或"我猜"前缀（`line` 本身已含不确定词，前缀可选）。

### 5.2 `SceneHintSelector.pick`

```
输入：area, period, weather
1. 过滤 scene_hints 中 area 匹配的行
2. 过滤 period 匹配（或为空=通用）
3. 过滤 weather 匹配（或为空=通用）
4. 过滤 condition 满足（eval_condition）
5. 按 priority 降序，同优先级按行序
6. 返回首行；无则返回空
```

`eval_condition`：
```
func eval_condition(cond: String) -> bool:
    if cond.is_empty() or cond == "always": return true
    for part in cond.split("&"):
        if not _eval_single(part): return false
    return true
```

### 5.3 `SystemMessages.get_line`

按 `msg_id` 查表，返回 `line` 和 `tone`。

## 六、UI 呈现（复用 `ui-001` 的 `NoticeArbiter`）

### 6.1 三类提示的视觉区分

| 类别 | 位置 | 样式 | 时长 | 可关闭 |
|---|---|---|---|---|
| NPC | 左下气泡 | 暖米色背景 + 头像 + speaker 名 | 5s | 是 |
| 系统 | 顶部居中横幅 | 冷灰背景，无头像，无 speaker | 3s | 否 |
| 场景 | 屏幕中下方 | 无背景，柔光文字，斜体 | 2.5s | 否 |

**不用颜色区分**（色盲不友好），用**位置 + 前缀 + 斜体**区分。

### 6.2 仲裁优先级

```
system (100) > npc (50) > scene (10)
```

- 系统提示出现时，抢占 NPC/场景位置，3s 后恢复。
- NPC 提示出现时，不抢占场景提示，但气泡覆盖在场景文字上方。
- 场景提示最低优先级，有 NPC/系统提示时**直接丢弃，不排队**。
